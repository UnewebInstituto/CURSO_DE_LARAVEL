### 1. Instalación de Composer y Laravel

**Teoría:**
Laravel gestiona sus dependencias a través de **Composer**, el gestor de paquetes de PHP. Composer es indispensable porque descarga tanto el núcleo de Laravel como todas las librerías de terceros necesarias para que el sistema funcione.

**Práctica:**

1. **Instalar Composer:** Descárgalo desde 
[getcomposer.org](https://getcomposer.org/). 

C:\Users\All Users\ComposerSetup\bin

C:\ProgramData\ComposerSetup\bin


Verifica con `composer --version` en tu terminal.
2. **Instalar el Instalador de Laravel (opcional pero recomendado):**
```bash

composer config -g cafile "C:/xampp/apache/bin/cacert.pem"

composer global require laravel/installer

```

3. **Crear un proyecto nuevo:**
```bash
laravel new nombre-del-proyecto

# O mediante Composer directamente:
composer create-project laravel/laravel nombre-del-proyecto

```
**********
ATENCIÓN:
Las opciones que estás viendo en tu terminal corresponden a los **Starter Kits** (kits de inicio) oficiales de Laravel. Estos kits están diseñados para acelerar drásticamente el desarrollo de tu aplicación, ya que te proporcionan toda la lógica y estructura necesaria para funciones comunes, especialmente la **autenticación de usuarios** (login, registro, recuperación de contraseña, etc.).

Aquí te explico qué significa cada opción para que elijas la que mejor se adapte a lo que buscas aprender o construir:

* **None (Ninguno):** Laravel instalará solo el esqueleto básico del framework. Es la opción ideal si quieres aprender a construir todo desde cero o si tu proyecto no requiere un sistema de usuarios predefinido.


* **React:** Instala Laravel junto con el framework de JavaScript **React**. Es la opción recomendada si ya tienes experiencia con React o si planeas construir una interfaz de usuario altamente interactiva y basada en componentes.


* 
**Svelte:** Instala Laravel integrado con **Svelte**, un framework de JavaScript moderno conocido por ser extremadamente ligero y rápido, ya que compila tu código en JavaScript puro durante el desarrollo.


* **Vue:** Instala Laravel junto con **Vue.js**. Esta es una combinación muy popular y tradicionalmente integrada en Laravel; ofrece una curva de aprendizaje amigable y mucha potencia para interfaces dinámicas.


* **Livewire:** Esta es la opción "estrella" para muchos desarrolladores de Laravel. **Livewire** te permite construir interfaces dinámicas y modernas usando únicamente **PHP**, sin necesidad de escribir código JavaScript complejo. Se integra a la perfección con Blade (el motor de vistas de Laravel).



### ¿Cuál deberías elegir?

* Si estás **aprendiendo los fundamentos** (MVC, rutas, vistas), te recomiendo seleccionar **`none`** o **`livewire`**. Livewire te mantendrá dentro de tu zona de confort con PHP y te permitirá ver resultados rápidos sin perderte en configuraciones complejas de JavaScript.


* Si tu objetivo es **desarrollo Frontend profesional** y ya dominas React o Vue, elige el kit correspondiente para aprovechar la potencia de esos ecosistemas dentro de tu proyecto Laravel.

La elección entre **Pest** y **PHPUnit** depende principalmente de tus preferencias personales sobre cómo prefieres escribir el código de tus pruebas, ya que ambos son excelentes y funcionan perfectamente con Laravel.

Aquí te presento los factores para ayudarte a decidir:

### 1. Pest (Opción recomendada para empezar)

Pest es un framework de pruebas construido **sobre** PHPUnit, diseñado para ser extremadamente intuitivo y legible.

* **Por qué elegirlo:** Tiene una sintaxis mucho más limpia y minimalista, inspirada en frameworks de pruebas modernos (como Jest en JavaScript). Es muy fácil de leer, lo que ayuda a que el código de tus pruebas se sienta casi como lenguaje natural.
* **Curva de aprendizaje:** Muy baja. Si eres nuevo en testing, Pest te hará el proceso mucho más amigable.
* **Ejemplo:**
```php
test('la página de inicio carga correctamente', function () {
    $this->get('/')->assertStatus(200);
});

```



### 2. PHPUnit (El estándar de la industria)

PHPUnit es la base sobre la que se asienta el ecosistema de pruebas de PHP desde hace muchos años.

* **Por qué elegirlo:** Es el estándar de facto. Si tu intención es trabajar en proyectos empresariales grandes o si necesitas integrar tus pruebas con herramientas de terceros que requieran configuraciones muy específicas, PHPUnit es la apuesta más segura y conservadora.
* **Curva de aprendizaje:** Un poco más técnica. Requiere definir clases y métodos con una estructura más rígida (basada en el estándar de Clases de PHP).
* **Ejemplo:**
```php
public function test_la_pagina_de_inicio_carga_correctamente()
{
    $this->get('/')->assertStatus(200);
}

```



---

### ¿Cuál elegir?

* **Elige Pest [0]** si quieres una experiencia de desarrollo más rápida, divertida y moderna. Es la opción preferida por la comunidad actual de Laravel debido a su legibilidad y simplicidad.


* **Elige PHPUnit [1]** si prefieres apegarte a la estructura clásica y tradicional, o si planeas en el futuro llevar tus conocimientos de testing a otros frameworks de PHP que no necesariamente usen Pest.

**Recomendación:** Para este curso de fundamentos, **selecciona `[0] Pest**`. Te permitirá enfocarte en aprender qué es lo que estás probando en lugar de luchar con la sintaxis de las clases de prueba.

BASES DE DATOS:
Esta es la fase final de la configuración de ** **. El instalador te está preguntando si deseas ejecutar las **migraciones de base de datos** predeterminadas.

### ¿Qué significa esto?

Las "migraciones" son esencialmente archivos de código (en PHP) que Laravel utiliza para crear las tablas necesarias en tu base de datos automáticamente.

* Al seleccionar **`yes`**, Laravel creará las tablas fundamentales (como la de `users`, `password_reset_tokens`, `failed_jobs`, etc.) directamente en tu base de datos **MariaDB**.
* **¿Por qué es importante?** Si no corres estas migraciones ahora, cuando intentes registrar un usuario o iniciar sesión en tu aplicación más adelante, Laravel no encontrará las tablas necesarias en la base de datos y recibirás un error de "Table not found".

### Paso previo necesario

Como elegiste **MariaDB**, asegúrate de que:

1. **XAMPP esté activo:** Debes tener el panel de control de XAMPP abierto y haber iniciado el servicio **MySQL** (que en XAMPP gestiona tanto MySQL como MariaDB).
2. **Base de datos creada:** Laravel necesita una base de datos donde guardar estas tablas. Antes de presionar "yes", asegúrate de haber creado una base de datos vacía (usualmente mediante **phpMyAdmin** en `http://localhost/phpmyadmin`) llamada ` `.
3. **Configuración `.env`:** Laravel debe conocer el nombre de esa base de datos. En la carpeta raíz de tu proyecto ` `, abre el archivo `.env` y busca estas líneas, asegurándote de que coincidan con tu configuración:
```env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE= 
DB_USERNAME=root
DB_PASSWORD=

```

**Recomendación:**
Responde **`yes`**. Es el comportamiento estándar para empezar a desarrollar. Si el proceso termina exitosamente, verás un mensaje confirmando que las tablas fueron creadas (ej. `Migrating: ...`).
